## 3. 使い方の流れ

1. 甲(公嗣さん)が `contract.html` を開き、**合言葉**を入れる → Apps Script が契約書ひな形を返す(`contract_templates`)。
2. ひな形を選び、項目・甲乙の氏名とメールを入力 → 甲が**手書きサイン**(枠を指/マウスでなぞる。PNG画像として保存)→ 送信(`contract_create`)。
3. 乙に署名用リンクがメールで届く(画面にもリンクとコピーボタンが出る)。
4. 乙がリンクを開いて内容確認(`contract_get`)→ 同意にチェック → 手書きサイン → 送信(`contract_sign`)。
5. 署名済みPDFがドライブ「電子契約」フォルダに保存され、甲乙の両方にPDF添付メールが届く。リンクは無効化。
6. 署名済みかどうかは `contract_status`(合言葉必須、本文などは返さない)で確認できる。

記録されるもの: 契約ID、作成日時、乙の署名日時、甲乙メール、乙の端末情報(UserAgent)、本文の SHA-256 ハッシュ(改ざん検知)。
※簡易的な合意記録。重要・高額な契約は専門家確認を推奨(ページ下部にも注記あり)。

## 4. ファイル構成(GitHub main)

| ファイル | 役割 |
|---|---|
| `contract.html` | 入口(合言葉)→ 作成 → 署名の1ページ。`?id=…&t=…` 付きで開くと乙の署名画面 |
| `Code.gs` | 予約・募集・電子契約の受付窓口(`doPost` / `doGet`)。`setup()` で「契約」シートも作る |
| `Contract.gs` | 電子契約の本体(作成・取得・署名・PDF作成・メール・状態確認) |
| `ContractTemplates.gs` | 契約書ひな形7種(合言葉が合ったときだけ返す) |
| `README.md` | セットアップ手順(電子契約は「電子契約(contract.html)のセットアップ」の節) |

ひな形7種: 業務委託兼ありがとう大学研修契約書【プレミアムプラン】／エアコン用部材レンタル基本契約書／ドクター水素浴＋ レンタル利用規約／業務委託契約書／秘密保持契約書(NDA)／売買契約書／簡易合意書(念書)

窓口(`kind` / `action`): `contract_templates`・`contract_create`・`contract_sign`・`contract_status`(POST)、`contract_get`(GET)

スクリプトプロパティ(キー名のみ): `CONTRACT_PASSCODE`(必須)、`SITE_URL`(署名リンク改ざん防止)、ほかに予約用の `NOTIFY_EMAIL` / `PAYPAL_ENV` / `PAYPAL_CLIENT_ID` / `PAYPAL_SECRET`

## 7. 注意点・既知のリスク

1. **`コード.gs` を丸ごと置き換えない**: 本番の `コード.gs` には「空き状況の表示」など、GitHub の `Code.gs` に無い機能がある可能性がある(未照合)。変更は必要な行だけ足す「部分更新」で行う。いずれ本番の全文を取り出して GitHub に反映し、ずれを解消したい(読み取り専用の取り出しプロンプトを使う。`clasp` はクラウドの Claude Code では使えない)。
2. **ひな形の文面が GitHub で見える可能性**: PR #4 でひな形を公開ページから外したが、`ContractTemplates.gs` 自体は GitHub(公開リポジトリなら誰でも閲覧可)に置いてある。研修費用などの金額を伏せたいなら、リポジトリを非公開にする/ひな形を Apps Script 側だけで管理する、のどちらかを公嗣さんに選んでもらう(未決定)。
3. `handleContractStatus_` の合言葉エラー文言が「作成用パスコードが違います」で、他(「合言葉が違います」)と揃っていない。軽微。
4. Claude Code(クラウド)からは github.io・Google にアクセスできないため、公開ページや Apps Script の動作確認は公嗣さんか Chrome の Claude が行う。
5. 合言葉を変えたら、テンプレ取得・作成・状態確認すべてで新しい合言葉が必要になる(紹介ノート等から `contract_status` を使っている場合はそちらも更新)。
